    API Specification: Global Standards & Authentication¶

    The Cloud Management Platform (CMP) Backend API is built on FastAPI. It serves as the programmatic control plane of the CNP ecosystem.

    1. Base URL¶

    All requests must be directed to the following base URLs:

    • Production API: https://cmp.3istor.com/api
    • Local Development: http://localhost:8000/api

    2. Authentication & Authorization¶

    All endpoints (except the /health check) require authentication using HTTP Bearer Tokens. These tokens are OpenID Connect (OIDC) JSON Web Tokens (JWTs) generated by Keycloak.

    [ Client Request ] ──► ( Authorization: Bearer <JWT> ) ──► [ API Endpoint ]

    Key Token Claims Inspected by the API:¶

    • sub: Unique Keycloak user UUID.
    • preferred_username: Username of the user (e.g. brian.perret).
    • groups: List of group memberships mapping to project RBAC boundaries (e.g. ["project-alpha-admins", "project-alpha-members"]).

    Example cURL Request:¶

    curl -X GET "https://cmp.3istor.com/api/deployments" \
  -H "Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -H "Content-Type: application/json"

    3. Global HTTP Status Codes¶

    The API strictly adheres to standard HTTP semantics to communicate the outcome of requests:

    Code Status Usage
    200 OK The request succeeded, and data is returned.
    201 Created Resource created (synchronous operations).
    202 Accepted Request accepted for processing (used for asynchronous SAGA tasks).
    204 No Content Deletion or modification succeeded with no payload to return.
    400 Bad Request Invalid payload or logic constraint violation.
    401 Unauthorized Token missing, invalid, or expired.
    403 Forbidden Authenticated, but lacks required project group permissions.
    404 Not Found Target resource does not exist.
    422 Unprocessable Pydantic validation failed on the request body schema.
    502 Bad Gateway Downstream proxy or integration (GitHub, Keycloak, Vault) failed.

    4. Standard Error Response Schemas¶

    To ensure predictable error handling on the frontend, all errors return structured JSON payloads.

    Standard Error (400, 401, 403, 404, 502)¶

    {
  "detail": "Detailed, human-readable error description explaining the failure."
}

    Validation Error (422 Unprocessable Entity)¶

    When a request body fails to validate against the defined Pydantic schema, FastAPI automatically generates a structured array pointing to the invalid fields:

    {
  "detail": [
    {
      "loc": [
        "body",
        "app_config",
        "project_name"
      ],
      "msg": "field required",
      "type": "value_error.missing"
    }
  ]
}

    Real-world Example: Missing Project-Name validation error¶

    # Requesting deployment without required project_name variable
curl -X POST "https://cmp.3istor.com/api/deployments" \
  -H "Authorization: Bearer eyJhbGci..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "my-app",
    "template_id": "kubernetes-fastapi",
    "provider_type": "kubernetes",
    "app_config": {
      "replica_count": 2
    }
  }'

    Response (422 Unprocessable Entity): 

    {
  "detail": [
    {
      "loc": ["body", "app_config", "project_name"],
      "msg": "field required",
      "type": "value_error.missing"
    }
  ]
}
