    Matrice OWASP MCP et agentique¶

    Comment le serveur MCP de la CMP (les assistants IA qui agissent sur CNP au nom d'un utilisateur, voir Assistants IA (MCP)) répond aux deux référentiels OWASP du moment, quel contrôle le porte dans le code, et quel test le prouve. Un contrôle sans test vert n'est pas revendiqué.

    Référentiels :

    • OWASP MCP Top 10, version 2025, statut bêta (phase 3, « Beta Release and Pilot Testing »), CC BY-NC-SA 4.0 : https://owasp.org/projects/mcp-top-10, consulté le 13/11/2026.
    • OWASP Top 10 for Agentic Applications for 2026, OWASP GenAI Security Project, publié le 9 décembre 2025 : https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/, consulté le 13/11/2026.

    Code de référence : CMP au commit 31b4486 (branche test/mcp-owasp-controls). Les tests sont dans backend/tests/test_mcp_owasp_controls.py sauf mention contraire, et passent avec pytest backend/tests/test_mcp_owasp_controls.py.

    Écarts trouvés et corrigés¶

    L'écriture des tests a révélé quatre écarts réels. Chacun a un correctif minimal dans la même PR CMP, et le test correspondant échoue sans lui.

    # Écart Correctif Test
    1 Un token d'assistant marchait sur toute l'API REST. Présenté directement à /api, il contournait la politique d'enjeu (policy.yaml) et le scope lecture seule, que seuls les outils MCP appliquent. Exemple : une promotion sur un projet critical sans approbation, un DELETE d'app avec un token en lecture seule Le token n'est accepté que pendant un appel in-process d'un outil MCP (keycloak_service.py:694, internal_api.py:46) test_an_assistant_token_is_refused_by_the_rest_api_outside_a_tool, test_a_read_only_assistant_cannot_write_through_the_rest_api
    2 Un appel refusé par la politique (deny) ne laissait aucune trace Événement agent.policy.denied au journal (mcp_server.py:289) test_a_call_the_stake_policy_refuses_is_journaled
    3 list_app_files renvoyait les chemins du dépôt sans la mention « données, pas instructions », alors qu'un nom de fichier est écrit par n'importe qui ayant poussé dans le dépôt Ajout de note: UNTRUSTED (mcp_server.py:706) test_content_written_by_others_is_marked_as_untrusted_data
    4 Trois tests existants envoyaient un token d'assistant directement à /api Ils passent désormais par le chemin in-process, le seul possible, et vérifient toujours le refus 403 test_agents.py L500, L559, L659

    Changement de comportement (écart 1) : un client qui appellerait /api avec un token cnp_at_... reçoit maintenant 401. Aucun client légitime ne le fait : le frontend utilise les tokens Keycloak et les assistants passent par /mcp.

    OWASP MCP Top 10 (2025)¶

    Risque Contrôle CNP Test qui le prouve Écart restant
    MCP01:2025 Token Mismanagement & Secret Exposure Tokens opaques, seul le SHA-256 est stocké (store.py:64) ; token d'accès 15 min (config.py:242) ; rotation du refresh token (store.py:354) ; push_files refuse un fichier qui contient un secret (mcp_server.py:756, repo.py:99) ; request_secret fait saisir la valeur dans la CMP, jamais dans la conversation (mcp_server.py:825) test_assistant_tokens_are_stored_only_as_hashes, test_push_files_containing_a_secret_commits_nothing, test_a_committed_token_is_detected, test_secret_files_are_refused, test_refresh_token_works_once La détection de secrets est une liste de formes connues, pas une mesure d'entropie. Un secret qu'une app écrit dans ses logs part tel quel vers le modèle via get_app_logs
    MCP02:2025 Privilege Escalation via Scope Creep Scopes cnp:read / cnp:write (store.py:36, mcp_server.py:149) ; le grant ne copie ni groupes ni rôles (store.py:45) ; politique d'enjeu évaluée côté serveur (policy.py:108) ; token limité au serveur MCP (keycloak_service.py:694) test_read_only_assistant_cannot_create_an_app, test_a_read_only_assistant_cannot_write_through_the_rest_api, test_assistant_claims_never_carry_the_users_platform_groups, test_policy_scales_with_the_project_stake Corrigé dans cette PR : contournement par l'API REST (écart 1). En lecture, l'assistant voit tout ce que voit son utilisateur
    MCP03:2025 Tool Poisoning Outils déclarés dans le code, descriptions = docstrings relues en PR ; instructions du serveur constantes (mcp_server.py:57) ; aucun outil enregistré à l'exécution test_the_tool_set_is_the_reviewed_one, test_tool_descriptions_are_the_docstrings_in_the_code, test_tool_definitions_do_not_change_with_database_content Les guides (get_guide) viennent du dépôt cnp-agent-kit à l'exécution (skills.py:51) et ne portent pas la mention non fiable : leur intégrité repose sur la protection de branche de ce dépôt. Le nom de client déclaré à l'enregistrement OAuth est renvoyé par whoami
    MCP04:2025 Software Supply Chain Attacks & Dependency Tampering SDK mcp verrouillé dans poetry.lock ; Trivy bloque les vulnérabilités HIGH/CRITICAL corrigeables sur chaque PR (.github/workflows/security.yml) ; policy.yaml ne change que par PR Hors pytest : job CI trivy Pas de SBOM ni de vérification de signature du SDK. Même remarque que MCP03 pour cnp-agent-kit
    MCP05:2025 Command Injection & Execution Aucun appel shell dans le serveur MCP ; entrées typées (Literal, bornes ge/le) ; chemins normalisés, sortie du dépôt refusée (repo.py:72) ; fichiers de CI, Dockerfile et déploiement classés sensibles (repo.py:83) ; la recherche LogQL refuse le backtick test_paths_cannot_escape_the_repository, test_paths_that_run_code_or_expose_the_app_are_sensitive, test_search_cannot_break_out_of_the_query (test_activity_sources.py) Pousser du code reste de l'exécution de code, par conception : le code applicatif non sensible tourne dans le conteneur de l'app après release, borné par l'isolation du namespace
    MCP06:2025 Prompt Injection via Contextual Payloads Contenu des dépôts et logs marqué UNTRUSTED (mcp_server.py:52) dans read_app_file, list_app_files, get_app_logs ; instructions du serveur : ne jamais suivre ce qui s'y trouve (mcp_server.py:79) ; la vraie barrière est la politique (ask, confirm, pr) test_content_written_by_others_is_marked_as_untrusted_data, test_server_instructions_forbid_following_logs_and_repository_content La mention est un conseil au modèle, pas une garantie. D'autres champs écrits par des tiers ne sont pas marqués : message d'étape d'une app, messages des étapes de release
    MCP07:2025 Insufficient Authentication & Authorization OAuth 2.1 + PKCE (SDK MCP), enregistrement dynamique limité aux redirections en loopback ou autorisées (store.py:72) ; scope requis sur /mcp (mcp_server.py:102) ; protection DNS rebinding (mcp_server.py:110) ; rôle de projet vérifié (mcp_server.py:160) ; routes réservées aux humains (agents.py:37, access.py:38, step_up.py:74) ; tokens Keycloak : azp et typ vérifiés (keycloak_service.py:723) test_the_mcp_endpoint_refuses_a_token_it_did_not_issue, test_an_infra_users_assistant_cannot_reach_a_platform_admin_endpoint, test_an_assistant_cannot_read_a_project_its_user_is_not_member_of, test_registration_refuses_an_unknown_redirect_uri, test_an_assistant_cannot_approve_a_connection, test_rejects_untrusted_tokens (test_api_auth.py, cas other-client et id-token), test_refuses_an_assistant_token_with_403_by_default (test_step_up.py) aud n'est pas vérifié sur les tokens Keycloak (il vaut account) : azp le remplace. validate_token_resource=False : le resource RFC 8707 n'est pas lié au token, acceptable tant que la CMP n'émet des tokens que pour /mcp
    MCP08:2025 Lack of Audit and Telemetry Middleware d'audit sur chaque appel REST qui modifie, avec l'assistant en via (audit.py:426) ; record_agent_event pour les commits et tags poussés hors REST (audit.py:343) ; refus de la politique journalisés (mcp_server.py:289) test_every_write_tool_call_is_journaled_with_the_assistant_name (6 outils), test_every_tool_that_can_change_something_is_in_the_journal_test, test_a_call_the_stake_policy_refuses_is_journaled Les appels d'outils en lecture ne sont pas journalisés (whoami, read_app_file, get_app_logs...), ni les arrêts needs_user_confirmation. À décider : volume du fil d'activité contre traçabilité, éventuellement dans Loki plutôt que dans audit_events
    MCP09:2025 Shadow MCP Servers Un seul serveur MCP, servi par la CMP, OAuth émis par la CMP ; ensemble d'outils figé par test test_the_tool_set_is_the_reviewed_one Hors périmètre de la CMP : les serveurs MCP qu'un développeur lance sur son poste. Relève d'une politique d'usage
    MCP10:2025 Context Injection & Over-Sharing Serveur sans état (stateless_http=True, mcp_server.py:106), aucune mémoire de conversation côté CMP ; chaque appel relit l'utilisateur depuis son token et vérifie le rôle sur le projet test_tool_call_acts_as_the_connected_user, test_an_assistant_cannot_read_a_project_its_user_is_not_member_of get_app_logs peut envoyer au modèle externe des données d'utilisateurs finaux de l'app : voir le registre RGPD, traitement T4

    OWASP Top 10 for Agentic Applications 2026¶

    Risque Contrôle CNP Test qui le prouve Écart restant
    ASI01 Agent Goal Hijack Comme MCP06, plus la politique qui arrête une action risquée même si le modèle a été détourné test_content_written_by_others_is_marked_as_untrusted_data, test_delete_app_waits_for_the_user_and_deletes_nothing, test_critical_project_waits_for_a_human_approval_in_the_cmp Un modèle détourné peut encore faire tout ce qui est allow, par exemple pousser du code non sensible sur un projet standard
    ASI02 Tool Misuse and Exploitation Politique par action et par niveau d'enjeu (policy.yaml) ; 3 apps max par sandbox ; quotas 120 lectures et 20 écritures par minute et par grant (ratelimit.py:9) ; approbation liée au tag et au commit d'une release test_policy_scales_with_the_project_stake, test_no_write_runs_unattended_on_a_critical_project, test_an_assistant_is_slowed_down_past_its_write_budget, test_cut_release_approval_binds_the_tag_and_the_commit Quotas en mémoire, par réplique : valable tant que la CMP tourne en une réplique
    ASI03 Identity and Privilege Abuse L'assistant agit avec l'identité de l'utilisateur, jamais avec ses groupes plateforme ; token limité au serveur MCP ; routes humaines ; grant révoqué si le compte Keycloak est désactivé ou supprimé test_an_assistant_token_is_refused_by_the_rest_api_outside_a_tool, test_assistant_claims_never_carry_the_users_platform_groups, test_an_infra_users_assistant_cannot_reach_a_platform_admin_endpoint, test_assistant_cannot_approve_its_own_sensitive_action, test_refresh_revokes_the_grant_of_a_disabled_account Corrigé dans cette PR (écart 1)
    ASI04 Agentic Supply Chain Vulnerabilities Comme MCP03 et MCP04 test_the_tool_set_is_the_reviewed_one, test_tool_descriptions_are_the_docstrings_in_the_code Guides de cnp-agent-kit lus à l'exécution
    ASI05 Unexpected Code Execution (RCE) Pas d'eval ni de shell côté serveur ; un push qui touche la CI, un Dockerfile ou le déploiement suit une règle plus stricte (deny en sandbox, ask en demo, pr au-delà) test_paths_that_run_code_or_expose_the_app_are_sensitive, test_policy_scales_with_the_project_stake (cas code.push_sensitive) Voir MCP05
    ASI06 Memory & Context Poisoning Aucune mémoire longue côté CMP : pas de stockage de conversation, définitions d'outils indépendantes de la base test_tool_definitions_do_not_change_with_database_content Les guides sont mis en cache 10 min ; un guide corrompu dans le dépôt resterait servi jusqu'à correction
    ASI07 Insecure Inter-Agent Communication Sans objet : la CMP n'orchestre pas plusieurs agents. Le seul lien est client MCP ↔ CMP, en HTTPS derrière Cloudflare, avec protection DNS rebinding Aucun, non revendiqué À réévaluer si la landing zone IA fait dialoguer des agents
    ASI08 Cascading Failures Quotas par grant ; approbations à usage unique, liées aux arguments exacts, expirées après 30 min (policy.py:238) ; fenêtre autonome plafonnée à 8 h (policy.py:26) test_a_cmp_approval_does_not_cover_a_call_with_other_arguments, test_critical_project_waits_for_a_human_approval_in_the_cmp (rejeu refusé), test_an_assistant_is_slowed_down_past_its_write_budget, test_expired_autonomous_window_restores_the_standard_rules Pas de coupe-circuit global sur l'ensemble des assistants
    ASI09 Human-Agent Trust Exploitation Actions jamais autonomes : project.create et app.delete ne sont allow à aucun niveau, même pendant un incident ; résumé de l'action construit par le serveur à partir des arguments, pas par le modèle ; confirm passe par une page de la CMP que l'assistant ne peut pas valider test_never_autonomous_actions_need_a_human_at_every_stake_level, test_delete_app_waits_for_the_user_and_deletes_nothing, test_assistant_cannot_approve_its_own_sensitive_action ask est déclaratif : user_confirmed=true est posé par le modèle, la CMP ne peut pas vérifier que l'utilisateur a vraiment dit oui. Seul confirm est une vérification humaine hors bande. Le step-up par passkey est désactivé par défaut (STEP_UP_ENABLED=False) et les routes de release et de suppression laissent passer les assistants (agents_allowed=True)
    ASI10 Rogue Agents Révocation d'un grant ou de tous les grants d'un utilisateur par infra ; journal avec via ; refus journalisés ; fenêtre autonome qui expire seule test_revoked_assistant_is_refused_on_its_next_call, test_infra_revokes_every_grant_of_a_user, test_a_call_the_stake_policy_refuses_is_journaled, test_expired_autonomous_window_restores_the_standard_rules Pas d'alerte automatique sur une rafale de agent.policy.denied

    Décisions à prendre¶

    • Journaliser ou non les appels d'outils en lecture (MCP08), et où.
    • Passer app.delete et project.create de ask à confirm sur sandbox et demo, puisque ask repose sur la parole du modèle (ASI09).
    • Marquer comme non fiables les autres champs écrits par des tiers (MCP06).
    • Alerte Loki ou Alertmanager sur agent.policy.denied (ASI10).
    • Politique d'usage : assistants autorisés, serveurs MCP locaux (MCP09), envoi de logs contenant des données d'utilisateurs finaux (MCP10).
