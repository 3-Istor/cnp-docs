# Static secrets

Every long-lived credential the platform still runs on, where it lives, who reads it, how
it is rotated today and what could replace it. This is step S6 of the
[access segregation](05-access-segregation.md) plan
([CNP-124](https://3istors.atlassian.net/browse/CNP-124)): zero static secret is the goal,
and the first step is to know them all and to measure their age.

Inventory taken on 2026-11-11 from `K3s` (`k8s/config/**`, `terraform/`), the CMP values,
`Cloud`, `cnp-project-base` and `app-templates`.

## Already done: CI has no secret

No workflow of the platform repositories (K3s, CMP, Cloud, cnp-projects,
cnp-project-base, app-templates, cnp-docs) reads a repository or organization secret.
They only use the per-run `GITHUB_TOKEN`, which GitHub issues for one job and revokes at
its end. Image builds push to GHCR with that token; the only CI that needs Vault
(`github-actions-dockair`) logs in with the GitHub OIDC token, not a stored one.
A leaked repository therefore leaks no credential, and there is nothing to rotate in
GitHub.

## How to read the inventory

- **Where**: Vault paths are on the `kvv2` mount unless stated otherwise. `tfvars` means
  the value is also a variable of `K3s/terraform`, so it sits in the operator's local
  `secrets.tfvars` and in the Terraform state (S3 bucket `istor-cnp-tfstate-*`, encrypted
  at rest, readable by whoever holds the state role).
- **Rotation today**: "never" means nothing in the platform changes it; a person would
  have to.
- **Target**: what removes the static value. "Stays static" means no federation exists
  for it; the answer is then a short rotation period and a narrow scope.
- **Risk**: what a leak gives, weighted by how many places hold it.
- **Owner**: `infra` is the platform team (`@3-Istor/infra`); app secrets belong to the
  team of the app.

**34 entries.** The five riskiest, in order:

1. **Keycloak master admin** (#1): owns every realm, so every login of the platform and
   of the projects. Three copies, one of them in a running pod.
2. **GitHub App private key** (#3): write access to the repositories Argo CD deploys
   from, so code in the cluster; it can also push to `main` of cnp-projects, which keeps
   a ruleset bypass for the CMP.
3. **OpenStack password** (#13): the project that hosts the cluster's nodes, handed to a
   CI outside the platform repositories as well.
4. **Ceph keys, RGW admin-ops first** (#17, #18): every bucket and volume, backups and
   logs included.
5. **Cloudflare API token** (#5): DNS of the zone, so certificates and traffic of every
   public route.

The CMP Vault token (#2) would top the list; it is left out because its replacement is
already deployed and only the removal remains.

## Findings to fix

- **App icon keys are outside Terraform.** `icons-s3-access-key-id` and
  `icons-s3-secret-access-key` are read by the CMP from `arcl-cmp/credentials`, but the
  `vault_kv_secret_v2.arcl_cmp_creds` resource does not declare them. The next
  `terraform apply` of `K3s/terraform` writes a version without them and the CMP loses
  its icon bucket. Add them as variables before the next apply.
- **One OIDC client secret in ten places** (#8). A leak from any app opens Grafana, the
  CMP and every protected app route.
- **Unused S3 keys** in `observability/config` (#28).
- **dockair CI** gets the platform's OpenStack and AWS credentials (#13, #14) through
  Vault. The login is federated, the credentials behind it are not.

## Measuring their age

Vault KV v2 keeps the `created_time` of every version of a path. The `secret-age`
CronJob (`K3s/k8s/config/observability/secret-age.yaml`) reads it every hour and pushes
`cnp_secret_age_days{path}` to VictoriaMetrics: the days since the current version of
each `kvv2` path was written.

- It logs in with its own service account (Vault role `secret-age`) whose policy only
  allows `list` and `read` on `kvv2/metadata/*`. It never reads a value.
- Alert `StaticSecretOlderThan90Days` (vmalert, `static-secrets.rules`) fires for any
  platform path older than 90 days. Project paths (`kvv2/projects/*`) are measured but
  not alerted on: their owners rotate them.
- Alert `SecretAgeExporterFailed` fires when a run fails, like `AuditArchiveFailed` for
  the audit archive.

```promql
# Oldest platform secrets first
sort_desc(max by (path) (max_over_time(cnp_secret_age_days{path!~"kvv2/projects/.*"}[2h])))
```

Limits:

- The age is per path, not per key. A path holding many keys (`arcl-cmp/credentials`
  holds 35) gets younger as soon as one key is written, even if the others stay.
  Splitting such paths by credential makes the metric honest.
- Not measured: the Rook-generated S3 keys (#19, Kubernetes Secrets), the `project-*`
  mounts (#34), the Vault auth configs (#16), the unseal keys (#12) and the Cloud
  Terraform variables (#21 to #23). They are outside `kvv2`.
